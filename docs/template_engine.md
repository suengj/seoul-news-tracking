# Template Recommendation & Extraction Engine

Deterministic template scoring, slot extraction, and rendering. No machine
learning, embeddings, or LLM calls anywhere in this module set — every
decision is a plain string/regex/dictionary rule or a YAML-driven text
substitution. See `docs/service_v1.md` for how this plugs into the
human-first select -> preview -> confirm flow, and
`docs/telegram_template_flow.md` for the Telegram wiring.

## Role of the 5,005 historical records vs. live Seoul input

`data/history_raw.db` (5,005 nationwide 재난문자 records, see
`docs/history_backfill.md`) is used **only** to sanity-check wording
patterns before writing the rules in `app/template_rules.py` and
`app/template_extractors.py` — see `docs/template_pattern_analysis.md` for
the candidate counts and example wording per template, generated by
`python -m app.commands.analyze_template_patterns`. That database is never
read by the live runtime, never modified, and its records are never sent
to Telegram.

## The seven templates (+ 2 support IDs)

Defined in `config/message_templates.yaml` — the human-managed source of
truth for all wording, emojis, line breaks, and required/optional slots:

1. `FLOOD_ADVISORY_ISSUED` — 홍수주의보 발효
2. `HEAVY_RAIN_CLEARED` — 호우특보 해제
3. `HEAVY_RAIN_DOWNGRADED` — 호우경보 → 주의보 하향
4. `HEAVY_RAIN_MULTI_LEVEL_ISSUED` — 호우경보+주의보 동시 발효
5. `HEATWAVE_UPGRADED` — 폭염주의보 → 경보 상향
6. `HEATWAVE_ADVISORY_ISSUED` — 폭염주의보 발효
7. `TROPICAL_NIGHT_ADVISORY_ISSUED` — 열대야주의보 발효
8. `ORIGINAL_ONLY` — resend the source message verbatim
9. `UNKNOWN` — no safe recommendation (`enabled: false`, never a button)

`enabled: false` actually hides a template from the Telegram selection
keyboard — `build_selection_keyboard()` in `app/telegram_sender.py` filters
by the YAML's own `enabled` field rather than assuming a hardcoded list.

## Rule score (`app/template_rules.py`)

`suggest_templates(message_text, sender_or_region, sent_at)` scores every
template as **matched required signal groups ÷ total signal groups**, then
subtracts a penalty per matched conflict group. A hand-authored match
ratio, **not a statistical probability** — no training data, no model.

In Service v1 this score is purely a secondary, non-actionable hint (see
`docs/service_v1.md`) — the operator always picks the template by hand;
nothing auto-selects or auto-sends based on this score.

**Fixed review issue**: `HEATWAVE_UPGRADED` used to require only 폭염경보 +
a transition word, which could false-positive on a plain warning that never
mentioned an advisory at all. It now requires **three** groups: 폭염주의보
**and** 폭염경보 **and** a transition word (상향/변경/대치) — a genuine
advisory-to-warning upgrade, not just a warning mention.

## Slot extraction (`app/template_extractors.py`)

`extract_slots(template_id, message_text, sender_or_region, sent_at)` never
invents a value. Priority per slot:

1. an explicit value in the message body (regex, anchored to an explicit
   word like "기준"/"부로"/"해제" — never a bare time/number alone)
2. the structured `sender_or_region` field (preferred over a body-parsed
   region when available)
3. `sent_at`, but **only** for `발표일시` ("announcement time" — by
   definition the message's own send time) — never for `기준일시`,
   `기준시각`, or `해제시각`

A slot missing from all of these is left out of `extracted_slots` and
listed in `missing_required_slots` — never guessed. **Extractors return
raw values only** — they never build fixed Korean prose themselves (a
flagged review issue: the old `HEATWAVE_UPGRADED` extractor used to
construct "...은(는) 폭염주의보가 유지됩니다." as a string; the fixed
sentence now lives entirely in the YAML template, see "Rendering" below).

### River-name extraction (`config/entity_dictionary.yaml`)

Priority order (spec-driven fix for the old "any word ending in 천/강"
over-broad regex):

1. an explicit labeled field ("하천명: ...", "대상하천: ...") anywhere in
   the text — `source="explicit_label"`
2. a river-suffix token found within a small window around a "홍수주의보"
   occurrence — narrower and safer than a global scan, `source="regex_match"`
3. a dictionary match against `config/entity_dictionary.yaml`'s small,
   human-editable `rivers:` list — `source="dictionary_match"`
4. the conservative global suffix regex as a last resort, gated by a small
   false-positive blocklist (`건강`, which ends in 강 but is "health," not a
   stream) — `source="regex_match"`, lower confidence

AI is deliberately **not** a tier here — it only ever runs on the explicit
"🤖 AI로 작성" button (`app/ai_client.py`), never as a silent extractor
fallback.

## Rendering (`app/template_renderer.py`)

Plain `{slot_name}` substitution — no Jinja2, no template inheritance — plus
one small conditional-block marker: `{#slot}...{/slot}`. If `slot` is
missing/empty the whole marked span (heading text and all) is dropped
before normal substitution runs; otherwise the span is kept with its own
`{slot}` placeholder(s) filled normally. This is what actually fixes two
flagged review issues cleanly, without any extractor-side prose-building:

- `HEAVY_RAIN_MULTI_LEVEL_ISSUED` no longer renders an empty "☔ 호우경보" /
  "☔ 호우주의보" heading when no region list was extracted — the heading
  and its placeholder are one conditional block per level
  (`{#경보지역}...{/경보지역}`, etc.).
- `HEATWAVE_UPGRADED`'s "...은(는) 폭염주의보가 유지됩니다." sentence is now
  written once in the YAML as `{#유지지역}{유지지역}은(는) 폭염주의보가
  유지됩니다.{/유지지역}` — the extractor only ever returns the raw
  `유지지역` value.

A render still:

- fails immediately if the YAML text references a placeholder not declared
  in `required_slots`/`optional_slots` (a config-authoring bug, caught here)
- fails if any required slot is missing or empty, listing exactly which
- substitutes every placeholder via `str.replace` (never regex-rescans
  substituted content, so a value's own `{}` characters are never
  misread as another placeholder) and collapses any 3+ blank-line run left
  behind by an omitted block down to one blank line

## Adding an eighth template

1. Add one entry to `config/message_templates.yaml`.
2. Add one rule spec entry to `_RULES` in `app/template_rules.py`.
3. Add one extractor function + a line in `_EXTRACTORS` in
   `app/template_extractors.py`.
4. Add its id + short code to `TEMPLATE_SHORT_CODES` and a slot in
   `_SELECTION_BUTTON_ROWS` in `app/telegram_sender.py`.
5. Add a test per file touched (see `tests/test_template_*.py`).

## Known limitations (engine-wide)

- Coverage against the historical archive is uneven: `HEAVY_RAIN_DOWNGRADED`,
  `HEAVY_RAIN_MULTI_LEVEL_ISSUED`, and `HEATWAVE_UPGRADED` had **zero**
  matching historical examples, so their rules are based on the template's
  own stated wording, not verified against a real historical message.
- The anchor-word requirement for time slots trades recall for precision —
  many genuine issuances without an explicit "기준"/"부로" phrase will
  correctly come back incomplete rather than auto-render (which is fine in
  Service v1, since a human confirms every render regardless).
- `TEMPLATE_RECOMMEND_THRESHOLD` is a single global cutoff across all seven
  templates — but since the rule score is now only a cosmetic hint (never
  gating anything), this matters much less than it did before Service v1.
