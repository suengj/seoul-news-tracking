# Template Recommendation Engine

Deterministic template suggestion, slot extraction, and rendering for *live*
Seoul SafeCity messages. No machine learning, embeddings, or LLM calls
anywhere in this feature — every decision is a plain string/regex rule or a
YAML-driven text substitution.

## Role of the 5,005 historical records vs. live Seoul input

`data/history_raw.db` (5,005 nationwide 재난문자 records, see
`docs/history_backfill.md`) is used **only** to sanity-check wording
patterns before writing the rules in `app/template_rules.py` and
`app/template_extractors.py` — see `docs/template_pattern_analysis.md` for
the actual candidate counts and example wording per template, generated by
`python -m app.commands.analyze_template_patterns`.

That database is never read by the live runtime (`poll_once`,
`run_telegram_bot`), never modified, and its records are never sent to
Telegram. Production input is exclusively the existing Seoul SafeCity
real-time collector (`app/collector.py`) — which is already Seoul-specific
by construction, so **no Seoul/non-Seoul classifier exists anywhere** in
this project. The historical records being nationwide has no bearing on
live behavior; it only broadened the wording samples available for rule
design.

## The seven templates (+ 2 support IDs)

Defined in `config/message_templates.yaml` — the human-managed source of
truth for all Telegram-rendered wording:

1. `FLOOD_ADVISORY_ISSUED` — 홍수주의보 발효
2. `HEAVY_RAIN_CLEARED` — 호우특보 해제
3. `HEAVY_RAIN_DOWNGRADED` — 호우경보 → 주의보 하향
4. `HEAVY_RAIN_MULTI_LEVEL_ISSUED` — 호우경보+주의보 동시 발효
5. `HEATWAVE_UPGRADED` — 폭염주의보 → 경보 상향
6. `HEATWAVE_ADVISORY_ISSUED` — 폭염주의보 발효
7. `TROPICAL_NIGHT_ADVISORY_ISSUED` — 열대야주의보 발효
8. `ORIGINAL_ONLY` — resend the source message verbatim
9. `UNKNOWN` — no safe recommendation (not a selectable button)

Each YAML entry has only `id`, `display_name`, `button_label`,
`required_slots`, `optional_slots`, `text` (plus `enabled`). Wording, line
breaks, emojis, and placeholders are exactly as authored — nothing in code
rewrites them.

## Rule score (`app/template_rules.py`)

`suggest_templates(message_text, sender_or_region, sent_at)` scores every
template as **matched required signal groups ÷ total signal groups**, then
subtracts a penalty per matched conflict group. This is a hand-authored
match ratio, **not a statistical probability** — there is no training data,
no model, no fitting step.

`recommend_template(..., threshold=TEMPLATE_RECOMMEND_THRESHOLD)` (default
`0.85`, env `TEMPLATE_RECOMMEND_THRESHOLD`) picks the highest-scoring
candidate that has **zero conflict signals**, **clears the threshold**, and
whose **required slots are actually extractable** from the message — in
that order. If nothing qualifies, the result is `None` (UNKNOWN); the caller
must not fabricate a recommendation.

## Slot extraction (`app/template_extractors.py`)

`extract_slots(template_id, message_text, sender_or_region, sent_at)` never
invents a value. Priority per slot:

1. an explicit value in the message body (regex, anchored to an explicit
   word like "기준"/"부로"/"해제" — never a bare time/number alone)
2. the structured `sender_or_region` field (always preferred over a
   body-parsed region when available)
3. `sent_at`, but **only** for `발표일시` ("announcement time" — this is,
   by definition, the message's own send time) — never for `기준일시`,
   `기준시각`, or `해제시각`, which describe a possibly-different reference
   time that must come from the body or not at all

A slot missing from all of these is left out of `extracted_slots` and
listed in `missing_required_slots` — it is never guessed.

Known extraction limitations (see `docs/template_pattern_analysis.md` for
the historical wording this was checked against):

- The time-anchor regex requires an explicit anchor word directly after the
  time; many real messages state a time without one, so those correctly do
  not auto-recommend a template with a non-`발표일시` time slot.
- The river-name regex (`...천`/`...강`) excludes matches immediately
  followed by an administrative suffix (시/군/구/동/읍/면/리/도) to avoid
  mistaking a region name (e.g. "예천군") for a river, but is still a
  heuristic and can occasionally miss or mismatch an unusual name.
- `경보지역`/`주의보지역`/`홍수지역` (labeled region lists for
  `HEAVY_RAIN_MULTI_LEVEL_ISSUED`) had zero historical candidates to check
  against (see the pattern analysis) — implemented from the template's own
  structure, not verified against a real example.

## Rendering (`app/template_renderer.py`)

Plain `{slot_name}` substitution — no Jinja2, no template inheritance. A
render:

- fails immediately if the YAML text references a placeholder not declared
  in `required_slots`/`optional_slots` (a config-authoring bug, caught here
  rather than silently left unresolved)
- fails if any required slot is missing or empty, listing exactly which
- otherwise substitutes every placeholder (`str.replace`, not regex — so a
  substituted value's own content, e.g. a URL, is never re-interpreted as
  another placeholder) and collapses any 3+ blank-line run left behind by
  an omitted optional block down to one blank line

## Adding an eighth template

1. Add one entry to `config/message_templates.yaml` (id, display_name,
   button_label, required/optional slots, text).
2. Add one rule spec entry to `_RULES` in `app/template_rules.py`.
3. Add one extractor function + a line in `_EXTRACTORS` in
   `app/template_extractors.py`.
4. Add its id + short code to `TEMPLATE_SHORT_CODES` and a slot in
   `_BUTTON_ROWS` in `app/telegram_sender.py`.
5. Add a test per file touched (see `tests/test_template_*.py` for the
   existing pattern).

## Future AI fallback (inactive)

`app/ai_fallback.py` contains two stubs (`suggest_template`,
`extract_slots`) that both raise `NotImplementedError`. Nothing imports
them. Per the module docstring, any future implementation must return
structured JSON with per-value evidence, be validated through
`app/template_renderer.py` before use, and never post directly to Telegram.

## Known limitations (engine-wide)

- Coverage against the historical archive is uneven: `HEAVY_RAIN_DOWNGRADED`,
  `HEAVY_RAIN_MULTI_LEVEL_ISSUED`, and `HEATWAVE_UPGRADED` had **zero**
  matching historical examples (see `docs/template_pattern_analysis.md`), so
  their rules are based on the template's own stated wording, not verified
  against a real message.
- The anchor-word requirement for time slots trades recall for precision —
  many genuine issuances without an explicit "기준"/"부로" phrase will
  correctly fall back to UNKNOWN or an incomplete-draft response rather
  than auto-render.
- `TEMPLATE_RECOMMEND_THRESHOLD` is a single global cutoff across all seven
  templates; a template with an inherently smaller number of signal groups
  reaches 1.0 more easily than one with more groups.
